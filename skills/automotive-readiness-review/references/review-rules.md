# Professional review boundaries

An agreed project/customer requirement manifest defines what must be complete. A/B/C component maturity, vehicle events such as PVS/0S/SOP and an organization's decision gates have explicit project-specific alignments.

Gate decisions require the same configuration across specification, test evidence, change disposition and product/process approval. Check upstream dependencies and the actual validation result. Recorded reviewer fields are input declarations; the tool is not an identity or signature service.

For PFMEA–Control Plan review, match operation and characteristic where available. A control for one characteristic must not clear another characteristic's gap. Missing reaction plans and uncarried special characteristics are potential inconsistencies; severity and control adequacy still require qualified engineering judgment. No AIAG/VDA Action Priority table is copied or calculated here.

A signed, valid, scoped concession may support a non-hard-stop exception only. The original conservative engine never uses a score average to erase a failed mandatory criterion. Customers may have more nuanced deviation procedures; encode an agreed procedure rather than infer one.

Cost assumptions are inputs. EAC is spent plus remaining direct and overhead costs. Report potential delay exposure separately unless an explicit accounting policy says otherwise. FS-only scheduling uses nonnegative integer days and lags. Actual completions must be historical and consistent with predecessors. Float is calculated to forecast finish; it is not contractual float. Resource conflicts are surfaced without automatic leveling.

Do not present a reconstructed workflow or synthetic dataset as delivered OEM work, external certification or industry validation. A real review record needs the actual practitioner's findings and a fixed dataset; entries in this local tool remain unauthenticated declarations.
